# tests/ — integration, visual regression, fixtures
Status: `npm run test:lua` and `npm run test:integration` are real. `test:lua` runs the Lua filter unit tests; `test:integration` runs the Remotion render test (task 004, needs a Chromium headless shell), the minimal-filter golden test (task 003) and the CLI tests (`validate.test.ts`, task 005; `cli-render.test.ts`, task 006), through the pinned Quarto. `test:visual` is still a placeholder until task 020.

What needs a test: `docs/testing.md`. Gates and runners: ADR-0010.

## Where tests live
| Kind | Location | Command |
| ---- | -------- | ------- |
| Gate scripts | `scripts/tests/` | `scripts/test.sh --all --suite scripts` |
| Unit (TS) | `packages/*/test/`, `renderer/remotion/test/` | `npm run check` |
| Unit (Lua) | `_extensions/video/tests/` | `npm run test:lua` |
| Integration | `tests/integration/` | `npm run test:integration` |
| Visual regression | `tests/visual/` | `npm run test:visual` |

## Layout
- `fixtures/projects/<task-slug>/` — minimal `.qmd` projects, one per behaviour,
  each with an `expected.json` (expected IR or diagnostics) where applicable.
- `fixtures/media/` — generated by `fixtures/media/generate.sh` (ffmpeg test
  patterns, tones). Commit the script, not large binaries (> 500 KB).
- `integration/` — CLI-level tests: spawn `video`, assert exit code, output,
  files.
- `visual/cases/<case>.json` — fixture project + frames to capture.
- `visual/references/<case>/<frame>.png` — approved stills.
- `visual/report/` — generated diff report; gitignored.

## Rules
- Each diagnostic code and each released component/preset has a fixture.
- Tests must not use the network and must not depend on the caller's cwd.
- Never delete, skip, or loosen a test to make a task pass.
- Updating references (`npm run test:visual:approve`) requires stating the
  intentional design change in the task's Completion log.
- Integration tests that encode video must keep fixtures short (≤ 2 s,
  ≤ 640×360) unless the task requires otherwise.
